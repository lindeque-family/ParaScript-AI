Solid models as text

A language for solid models.

A language model understands and writes language well. A prompt that asks it to produce a 3D object asks for something else: surfaces arranged in space, with a facing and a place. That is where a direct answer falls apart.

ParaScript keeps the model on the side it is good at. The model describes the solid in this language. The workspace compiles that description and produces the solid.

A face is a formula. A part is a function of its sizes. A join seats one part on another by the anchors they share.

For a language model

Read /language.md before writing a script. That page is the language this compiler accepts, and it starts with the guidance for a language model: the file's sizes live in parameters, pi is the shared constant, a cylinder is one Tube and two Disk faces, a plate is a square Box, |> pipes a value, and a pattern reads the anchors of the base part it is given. A vector is Vector(coords: coords, x:, y:, z:). A solid that builds geometry is coords =>, and so is expose. A script cannot construct that coordinate system. join takes it last and ignores it, so the solid is join(...), and a component does not expose it. frame.coords does not typecheck. A direction a mate needs is an anchor. A point moves with offset(x:, y:, z:). Two vectors combine with add(vector:) or subtract(vector:). A tuple is (1.0, true), taken apart with let (n, flag) = pair in. integers(start: 0.0, count: 5.0) is [0.0, 1.0, 2.0, 3.0, 4.0]. The same explanation for a person is /language.

The lessons on that page are: write each face and each solid once, a plate is a square Box, rectangular_pattern returns the grid of points, and map builds a cylinder per point so the radius and height can follow the location. subtract_cylinders cuts that list out of the plate. /llms.txt lists the same lessons.

The index of these pages is /llms.txt. There is no upload API. Write the script, then a person pastes it into /workspace and presses Run solver.
